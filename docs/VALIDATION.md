## Ограничение проверки WFP

Read-only --status из неповышенного процесса получил
FwpmFilterCreateEnumHandle0: 0x00000005 (Access denied).
Этот отказ не является результатом проверки самой политики.
CLI отображает отказ и возвращает код 5; требуется elevated процесс.
Не делается вывод, что protection ON/OFF, только из этого отказа.

На рабочей машине не выполнялись --enable, --disable, --uninstall-clean,
изменение firewall, установка Guard или регистрация его startup task.
Сетевой leak test не запускался: реализованы команда и кнопка для явного запуска.

## Не подтверждено

Реальная boot-time/persistent фильтрация, reauthorization старых соединений,
конфликтующие фильтры, socket attribution, смена сетей, BFE restart,
отсутствие пакетов на физическом адаптере, установка/удаление/автозапуск
в реальной Windows VM.

Статус удалённой сборки для конкретного коммита проверяется в
[GitHub Actions](https://github.com/ivanshcherbakov/hiddify-guard/actions).
Результат CI сам по себе не подтверждает перечисленные живые сценарии.

Это обязательные отдельные задачи из ACCEPTANCE.md и docs/tasks/.
Наличие готового установщика не означает готовность стабильного публичного релиза.

23 ноября 2026 года. Основа `f356cb0fdc943be0b821d400b81002cc5c9c111b`,
ветка `review/wfp-vm-f356cb0`. Windows x64, версия ядра `10.0.26300.0`,

Эта среда использовалась для сборки и unit-тестов без вызовов WFP,
запуска Guard/Hiddify и сетевых проб. Версии Windows и Hiddify в госте
не установлены, выделенная VM не предоставлена.

Сборка выполнялась с `--no-restore --disable-build-servers -m:1
-p:UseSharedCompilation=false /nr:false`. Тесты выполнялись с
`--no-build --no-restore --disable-build-servers`, результат сохранён
в TRX. Требуется локальный транспорт VSTest. Ранние попытки в ограниченной
среде отменили параллельную сборку и задержали запуск раннера. Последующие
запуски завершились успешно.

Проверка по SDK подтверждает бит провайдера `0x10`, бит фильтра `0x20`
и флаги включения boot-time и disabled при перечислении `0x08 | 0x10`.
Применимость выбранных ALE-слоёв при ранней загрузке и фактический охват
перечисления проверяются в госте. Документы Microsoft расходятся в описании
провайдера с пустым `serviceName`, поэтому требуются снимки до и после
холодной загрузки и наблюдение трафика. [Windows SDK](https://github.com/microsoft/win32metadata/blob/main/generation/WinSDK/RecompiledIdlHeaders/shared/fwpmtypes.h) · [FWPM_PROVIDER0](https://learn.microsoft.com/en-us/windows/win32/api/fwpmtypes/ns-fwpmtypes-fwpm_provider0) · [Object Management](https://learn.microsoft.com/en-us/windows/win32/fwp/object-management)

Первичные данные этой проверки — журналы сборки и TRX. Пакетные захваты,
снимки WFP и коды выполнения команд в госте отсутствуют. Все живые
сценарии перечислены в ACCEPTANCE.md.
