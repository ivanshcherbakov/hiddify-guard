# Приёмка до стабильного выпуска

Без заполненного протокола 0.1.0 остаётся проверочной версией.
Unit-тесты не заменяют сетевую приёмку.

## Результат независимого ревью

23 ноября 2026 года проверен исходный коммит
`f356cb0fdc943be0b821d400b81002cc5c9c111b`. Вердикт для стабильного выпуска —
**не готово**. Для сетевых гарантий данных пока недостаточно. Сборка и unit-тесты
прошли, но выделенная VM для активных испытаний не была предоставлена.
Снимков WFP, packet capture и подтверждения восстановления сети нет.

Исходная политика разрешала TUN по одному локальному адресу. В патче
исключение требует точный адрес обнаруженного TUN и LUID исходящего интерфейса.
Дефолтные подсети служат для обнаружения, самостоятельных разрешений для них
нет. Перенос существующей политики, пересоздание адаптера и повторная
авторизация при смене маршрута требуют VM-проверки.
Прежние разрешения продолжают работать до успешной замены. Простой
`--status` их не мигрирует. На Hiddify 5.9.8 при холодном старте отдельно
сверить путь и PID движка с AppId. [Описание релиза Hiddify](https://github.com/hiddify/hiddify-app/discussions/2583)

Слой `ALE_AUTH_CONNECT` покрывает исходящую авторизацию ALE. Входящие
потоки авторизуются на `ALE_AUTH_RECV_ACCEPT`, а пересылаемые IP-пакеты
нужно проверять отдельно. Это блокирует заявление о полном покрытии исходящего
трафика. [Модель потоков ALE](https://learn.microsoft.com/en-us/windows/win32/fwp/ale-stateful-filtering)

## Сценарии

Живые сценарии: отдельная Windows 10/11 x64 VM со снимком, локальной
консолью и проверенным восстановлением. Не используйте единственный
удалённый доступ. Не отключайте существующую защиту пользователя ради теста.

| Сценарий | Доказательство | Статус |
|---|---|---|
| Build/unit-тесты | exit code/TRX | исходник 28/28, патч 45/45, см. VALIDATION.md |
| Publish/Inno | артефакты/SHA256 | см. VALIDATION.md |
| Первая установка | ACL/ярлыки, защита не включена автоматически | не проверено в VM |
| Защита OFF | TCP4/TCP6 и UDP DNS доступны через каждый тестовый адаптер | не проверено в VM |
| ON без TUN | TCP4/TCP6/DNS не уходят физически, DHCP/loopback работают | не проверено в VM |
| Холодный старт Hiddify | подключение из блокированного состояния | не проверено в VM |
| VPN работает | успешный туннель, прямые пробы закреплены за обычными NIC | не проверено в VM |
| Краш Hiddify | нет прямого TCP/UDP/DNS | не проверено в VM |
| Старые соединения | длительные TCP/UDP, установленные до включения | не проверено в VM |
| Входящие и пересылаемые потоки | ответы и пакеты на обычном NIC | не проверено в VM |
| Ребут/BFE handoff | ранний packet capture, оба lifetime набора | не проверено в VM |
| Restart BFE | снимки до/после и непрерывный захват, если поддерживается | не проверено в VM |
| Сон/смена сети/IPv6 | новые адреса и маршруты без окна утечки | не проверено в VM |
| Адрес TUN и обычный NIC | разрешающее условие для TUN не совпадает с обычным egress | не проверено в VM |
| Чужие allow-правила | provider/sublayer/hard permit | не проверено в VM |
| AllowLan=true/false | отдельно подтверждены LAN, DHCP, loopback и внешний трафик | не проверено в VM |
| Закрытие/краш Guard | политика остаётся | не проверено в VM |
| Ручное выключение | только свои объекты удалены, сеть восстановлена | не проверено в VM |
| Удаление при ON | cleanup до файлов, сеть восстановлена | не проверено в VM |
| Ошибка cleanup | удаление остановлено, exe сохранён | не проверено в VM |
| Обновление | трей закрыт, политика не выключена | не проверено в VM |
| Startup | interactive/highest, правильный пользователь, не SYSTEM | не проверено в VM |
| Single instance | одно окно, повторный запуск активирует его | не проверено в VM |
| GitHub CI/Release | URL успешного run и проверенные артефакты | CI — см. Actions для коммита; release требует отдельной проверки |

Сохраните Windows/Hiddify версии, commit/хэш сборки, схему VM, IPv6,
начальные/финальные собственные фильтры, команды/коды и packet capture.
Отметьте разрешённые DHCP/ARP/LAN и сокеты Hiddify как намеренные исключения.
Завершение живого теста и восстановление выполняет оператор явно;
таймер автоотключения в рабочую программу не добавляется.
