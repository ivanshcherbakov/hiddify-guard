Проведи независимый аудит исходников Hiddify Guard без виртуальной машины
и без переключения сетевых фильтров на каком-либо компьютере.

Репозиторий: https://github.com/ivanshcherbakov/hiddify-guard.git
Склонируй актуальную main, зафиксируй SHA и работай в отдельной локальной ветке.
Прочитай AGENTS.md, docs/REQUIREMENTS.md, docs/HANDOFF.md, docs/VALIDATION.md
и docs/tasks/CODE-REVIEW-NO-VM.md. Задание WFP-VM-REVIEW.txt сейчас не выполняй.

ЦЕЛЬ

Найди подтверждённые дефекты исходников, добавь тесты чистой логики
и предложи минимальные исправления. Проверка реальной фильтрации, загрузки,
сетевых утечек и установки остаётся за отдельным исполнителем с Windows VM.

ОГРАНИЧЕНИЯ

- VM и права администратора не нужны.
- Не запускай --enable, --disable, --uninstall-clean, --leak-test,
  обычный GUI, установщик, Hyper-V setup или реальные WFP-вызовы.
- Не меняй VPN, firewall, BFE, службы, задачи, маршруты, Defender и настройки ОС.
- Не проверяй соединения с внешними TCP/DNS/HTTPS-целями.
- Не устанавливай драйверы и не инициируй перезагрузку.
- Тесты файловой логики выполняй только в собственных временных каталогах.
  Настоящий ProgramData не изменяй.
- Не удаляй и не пропускай Windows-тесты, чтобы получить зелёный результат.
- Не меняй постоянные GUID и не добавляй автоматическое Disable.
- Не отправляй код в main и не публикуй релизы. Верни патч/commit для ревью.

ПРОВЕРКИ

1. Сверь native ABI, offsets, union и байтовый порядок с первичными
   источниками Microsoft/Windows SDK. Это статическая проверка,
   а не доказательство успешной установки правил.
2. Проверь выделение и освобождение unmanaged memory, appId, enum handles,
   исключения при частичной инициализации и освобождение при ошибках.
3. Проверь begin/add/commit/abort, сохранение исходной ошибки, откат,
   идемпотентную очистку и ограничения владения provider/sublayer.
   Используй FakeSession и имитацию отказов, не настоящее WFP.
4. Проверь JSON, атомарную запись и откат настроек при ошибке политики.
   Разбери ACL, владельца, reparse points и поведение логирования
   из неповышенного процесса. Не изменяй системные ACL ради эксперимента.
5. Проверь, не может ли некорректная модель породить широкое allow-правило:
   /0, несогласованную IP-семью, конфликт ключей, лишние приложения.
6. Проверь чистую логику диагностики: таймаут, отмену, отсутствие IPv6,
   DNS ID/QR, смену состояния и невозможность объявить утечки отсутствующими
   только по неудачному соединению.
7. Покрой найденные дефекты содержательными regression-тестами.
   Не добавляй тесты, которые просто повторяют строки реализации.

СБОРКА

На Windows с .NET 8 SDK без повышения прав:
dotnet build src/HiddifyGuard.sln -c Release
dotnet test src/HiddifyGuard.sln -c Release

Эти unit-тесты используют fake policy backend и не включают kill switch.
Если рабочая среда Linux/macOS, выполни доступное статическое ревью,
а Windows build/test подтверди результатом CI windows-latest либо явно
отметь ограничение. Не подменяй Windows API ради формального прохождения.

РЕЗУЛЬТАТ

- SHA исходной версии.
- Список подтверждённых дефектов: серьёзность, путь/строки, воспроизведение.
- Минимальный diff/commit и объяснение исправлений.
- Команды, exit codes и результаты тестов.
- Отдельно: гипотезы и вопросы для будущей VM-приёмки.
- Не утверждай, что реальные сетевые утечки исключены: это задание
  не выполняет активную проверку WFP.
