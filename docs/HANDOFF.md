# Передача задачи сотруднику с Codex

Разработчику достаточно исходников и одной карточки docs/tasks/.
История чата и доступ к аккаунту владельца не нужны.
Пароли, подписки VPN, ключи и адреса личных серверов в пакет не входят.

## Работа через GitHub

Основной источник:
[ivanshcherbakov/hiddify-guard](https://github.com/ivanshcherbakov/hiddify-guard).
Коллеге достаточно ссылки на репозиторий и задания открыть
docs/prompts/CODE-REVIEW-NO-VM.txt и выполнить его инструкции.
После клонирования зафиксируйте SHA и создайте отдельную локальную ветку.
Изменения возвращаются патчем или, по поручению владельца, pull request.

## Текущее задание коллеге: без VM

Полный промпт:
[CODE-REVIEW-NO-VM.txt](prompts/CODE-REVIEW-NO-VM.txt).
Это ревью исходников и unit-тесты с fake backend, без elevation, включения
фильтров и изменения сети. Для Windows-тестов подходит обычный ПК или CI.
Границы правок указаны в [карточке](tasks/CODE-REVIEW-NO-VM.md).

Подготовка гостевой Windows остаётся за локальным оператором:
[VM-SETUP.md](VM-SETUP.md).

## Отдельное задание на проверку WFP в готовой VM

Полный промпт для Codex сохранён в
[prompts/WFP-VM-REVIEW.txt](prompts/WFP-VM-REVIEW.txt).
Файл доступен и в GitHub, и в source ZIP. Его содержимое можно вставить в Codex;
в репозитории находятся исходники и все перечисленные в задании документы.

## Процесс

1. Зафиксируйте commit SHA. Для автономной передачи можно подготовить
   неизменяемый архив командой ./scripts/package-handoff.ps1.
2. Выберите карточку, укажите исполнителя, срок, границы файлов и Windows VM.
3. WFP и uninstall проверяет отдельный специалист, не только автор кода.
4. Работайте в разных ветках/копиях, не правьте один файл одновременно.
5. Интегратор переносит проверенный commit/diff. Публикация — отдельное поручение.

## Контракты и владельцы

| Контракт | Файлы под src |
|---|---|
| Модель/стабильные ключи | HiddifyGuard.Core/Policy/PolicyPlan.cs |
| Транзакции/статус/IWfpSession | HiddifyGuard.Core/Policy/PolicyEngine.cs |
| Win32/память/ABI | HiddifyGuard.Core/Native/ |
| Поиск/события/состояния | HiddifyGuard.Core/Discovery/ |
| Настройки/ACL/логи | HiddifyGuard.Core/Storage/ |
| Пробы/вердикты | HiddifyGuard.Core/Diagnostics/ |
| Оркестрация/mutex | HiddifyGuard.Core/GuardController.cs |
| GUI/CLI/трей/язык | HiddifyGuard.App/ |
| Чистые тесты | HiddifyGuard.Core.Tests/ |

IWfpSession позволяет проверять отказы без изменения сети.
Изменение контракта сначала согласуется с интегратором.

## Готовый промпт

    Прочитай AGENTS.md, docs/REQUIREMENTS.md, docs/HANDOFF.md и
    docs/tasks/<карточка>.md. Выполни только карточку.
    Сохрани совместимость контрактов и стабильные GUID.
    Собери Release и выполни dotnet test.
    Не включай фильтры на рабочей машине, не меняй VPN, задачи автозапуска,
    Defender или чужие фильтры. Живые проверки — только в выделенной VM
    по явной команде оператора. Не публикуй и не отправляй код без поручения.
    Верни diff/commit, изменённые файлы, результаты команд, оставшиеся риски
    и воспроизводимые доказательства.

## Приём результата

- Build без предупреждений, тесты не отключены.
- Нет автоматического выключения защиты или удаления чужой политики.
- Ошибки add/commit не оставляют частичную политику.
- "Проверено", "не проверено" и "не удалось проверить" различаются.
- Нет VPN-секретов, пользовательских URL и истории браузера в evidence.
- Native/cleanup изменения прошли независимое ревью.
- Обновлены acceptance и документация поведения.

Передача не означает автоматическую рассылку или предоставление GitHub-доступа.
Доступ выдаёт владелец. Source ZIP исключает .git/dist/bin/obj и файлы вне репозитория.
