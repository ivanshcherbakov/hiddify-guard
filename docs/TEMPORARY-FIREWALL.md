# Временный режим через Брандмауэр Windows

Отдельные PowerShell-скрипты для временной ручной конфигурации Windows Firewall.
Они не запускают WFP-ядро приложения Hiddify Guard.
Требуется Windows, PowerShell 7.2+ и повышение прав.

## Механизм

- До включения экспортируется исходная политика в before.wfw и проверяется SHA256.
- На рабочем столе создаётся ярлык Hiddify Temporary - RESTORE firewall.
  Он запускает штатный netsh с UAC и импортирует исходный backup.
- Разрешения для точного TUN-интерфейса и его адресов, loopback, DHCP
  и локальной сети добавляются первыми.
- Внешние соединения разрешаются проверенному процессу ядра только к
  наблюдавшимся адресам/портам TCP-транспорта и через физический адаптер.
  Общего разрешения Hiddify на любые внешние адреса нет.
- Старые локальные outbound allow-правила временно отключаются.
- В последнюю очередь включаются Domain/Private/Public и исходящий default Block.
- Явный Block All не создаётся: в Windows Firewall он перекрыл бы разрешения.
- Службы, маршруты, Hiddify и сторонние WFP-provider не переключаются.
- Автоматического отката по таймеру, потере связи или завершению скрипта нет.

DHCP привязан к службе Dhcp в svchost.exe и нужным портам.
IPv6 neighbor discovery разрешён только для локального обмена.
LAN означает обнаруженные подсети физических адаптеров; опция по умолчанию включена.
Локальные TCP/UDP-разрешения исключают порты 53 и 853, чтобы не открыть
прямой DNS/DoT через домашний маршрутизатор. LAN остаётся намеренным исключением.

## Подготовка

В повышенной PowerShell 7:

    ./scripts/temporary/TemporaryFirewall.ps1 -Mode Prepare

Prepare читает конфигурацию, экспортирует backup и создаёт ярлык.
Правила и профили firewall на этом этапе не меняются.
Итог записывается локально в:

    %ProgramData%\HiddifyGuardTemporary\prepare-result.json

При ошибке подготовки:

    %ProgramData%\HiddifyGuardTemporary\prepare-error.txt

State и backup хранятся в защищённом каталоге ProgramData, не в репозитории.
Ready должен быть true. Нужны работающий TUN, проверенный путь процесса ядра,
маршрут через TUN и отсутствие неконтролируемых исключений/конфликтов.
Повторный Prepare может обновить план ещё не включённой сессии,
но откажется использовать изменившуюся исходную firewall-политику.

Проверка плана без elevation и изменения правил:

    ./scripts/temporary/Test-Plan.ps1

Тест использует временный ярлык и fake backend; настоящие firewall-команды
при проверке порядка и отказов заменены имитацией.

## Включение

Только при доступной локальной клавиатуре/экране и проверенном ярлыке восстановления:

    ./scripts/temporary/TemporaryFirewall.ps1 -Mode Enable -LocalConsoleConfirmed
    ./scripts/temporary/TemporaryFirewall.ps1 -Mode Status

Активация перепроверяет план и исходную политику.
Гарантии отсутствия краткого разрыва существующих соединений нет.
Если изменения оборвут связь, используйте заранее созданный локальный ярлык.

Status проверяет эффективные профили и оставшиеся outbound-разрешения.
Это проверка конфигурации, а не доказательство отсутствия пакетов.
Настоящие пробы выполняются отдельным явным действием.
Смена VPN-сервера/порта или физического адаптера потребует ручного
восстановления и новой подготовки. UDP-only транспорт этим вариантом
не подхватывается: подготовка должна обнаружить TCP-транспорт.

## Ручное восстановление

Дважды нажать Hiddify Temporary - RESTORE firewall и подтвердить UAC.
Альтернатива в повышенной PowerShell 7:

    ./scripts/temporary/TemporaryFirewall.ps1 -Mode Restore

Восстановится полная политика на момент Prepare, включая исходное состояние
профилей. Поэтому изменения firewall, сделанные другими программами после
подготовки, при восстановлении будут потеряны. Не устанавливайте и не
перенастраивайте сетевые приложения во время этой временной сессии.
Все backup сохраняются; чужие WFP-provider не удаляются.

После Restore новый Prepare создаёт новую сессию.
Если выполнен импорт непосредственно ярлыком, поле RecordedStage может
отставать от фактической конфигурации: ориентируйтесь на эффективные профили
и правила, затем выполните Restore через скрипт для фиксации состояния.

## Границы надёжности

Это ручной whitelist Windows Firewall, а не обещание "ни байта никогда".
Новое allow-правило, добавленное другой программой с достаточными правами,
может обойти default Block. GPO, IPsec и Windows service/app isolation
требуют отдельного учёта; неконтролируемые видимые исключения блокируют подготовку.
Boot-time, уже установленные и входящие потоки не объявляются проверенными
по одному успешному Status. Возможность холодного старта VPN проверяется отдельно.
Туннель после пересоздания может потребовать обновления временной сессии.
Если для холодного старта ядру нужен DNS вне туннеля, запуск после ребута
может не состояться: потребуется настройка сервера по IP или подходящий
способ bootstrap внутри VPN-клиента. Автоматическое открытие DNS не добавляется.
